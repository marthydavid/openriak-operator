# Agent Instructions for OpenRiak Operator Development

Guidance for agents working on the OpenRiak Operator. `CLAUDE.md` holds the detailed, current rules
(build and lint versions, test patterns, status reporting, riak-admin behaviour, images, releases);
this file is the short orientation. When the two disagree, `CLAUDE.md` wins.

## Project Overview

A Kubernetes operator for Riak KV, built with kubebuilder (Go 1.25, controller-runtime v0.23, k8s
libraries 0.35). Targets OpenShift/OKD 4.21 and 4.22 and AKS. CRDs (`riak.openriak.io/v1`):
- **RiakCluster**: the cluster (StatefulSet, Services, TLS, monitoring)
- **RiakBucket**: bucket type and bucket provisioning
- **RiakUser**: Riak user, certificate source and grants

Users authenticate with **mTLS client certificates only** (no passwords). A user's certificate comes from
cert-manager (`certificateRef.issuerRef`) or an external CA (`certificateRef.externalSecretName`, with the CA
listed in `RiakCluster.spec.tls.additionalClientCAs`). The node certificate always comes from cert-manager.
See `docs/mtls.md`.

## Key Architecture Points

### Controllers
- `internal/controller/`: one reconciler per CRD, plus `status.go` (shared status helpers), `tls.go` and
  `trust.go` (certificates and the trust bundle `<cluster>-tls-trust`), `monitoring.go` and `metrics.go`
- Reconcile order: get resource, handle deletion first, add finalizer, initialise status, business logic
- Keep `RiakUserReconciler.Reconcile` under the `gocyclo` limit by extracting helpers

### Riak Management
- `internal/riak/executor.go`: runs `kubectl exec ... riak-admin` (argument array, no shell)
- `internal/riak/manager.go`: high-level operations (join, create bucket, security, grants)

**Riak has no HTTP management API.** Everything goes through
`kubectl exec -n <ns> <pod> -c riak -- riak-admin <command>`.

**`riak-admin` exits 0 when a command fails.** The executor turns Riak's printed error into a Go error;
idempotent callers match the specific reason they tolerate. Test mocks should return real riak-admin output.

## Common Tasks

### Add a Riak operation
1. Low-level method on `Executor` (`executor.go`)
2. High-level method on `Manager` (`manager.go`)
3. Call it from the controller's Reconcile

### Change a CRD
1. Edit `api/v1/*_types.go` (validation markers drive the API server's checks; do not write controller code
   for values the schema already rejects, for example empty `grants[].resource`)
2. `make generate manifests`. `make manifests` also copies the CRDs into
   `charts/openriak-operator/files/crds/`, which the chart renders from `templates/crds.yaml`; CI fails when
   that copy differs from `config/crd/bases`
3. Update `docs/crds/*.md` and the examples

### Fix controller issues
1. Logs: `kubectl logs -n openriak-system -l control-plane=controller-manager`
2. Report state through `setCondition` and the status helpers; skip status writes when nothing changed
3. Use finalizers for cleanup

## CRD Design Patterns

```go
type <Resource>Status struct {
    Phase          <ResourcePhase>   // Creating, Ready, Failed
    Conditions     []metav1.Condition
    Error          string
    LastUpdateTime *metav1.Time
}
```

Status describes what was applied, not what was requested. Certificate readiness is not part of the phase.

## Build, test and lint

```bash
go build ./...
go test ./internal/... -timeout 180s                    # envtest + riak package
go test ./internal/... -coverprofile cover.out -timeout 180s && go tool cover -func cover.out
hack/pre-push.sh                                        # gofmt + vet + pinned golangci-lint + tests: before EVERY push
make test-stressapp test-soak-report                    # offline tests of the stress client and chart generator
```

Coverage target is 85% or more on `internal/controller` and `internal/riak`. Use the pinned linter
(`make lint`, golangci-lint v2.14.0), never a globally installed one. `test/e2e` needs a live cluster.

### Executor injection for controller tests

`Executor *riak.Executor` on the bucket and user reconcilers is nil in production (a real executor) and an
injected one in tests:

```go
noopRunner := func(_ context.Context, _ string, _ ...string) (string, error) { return "", nil }
r := &RiakBucketReconciler{
    Client:   k8sClient,
    Scheme:   k8sClient.Scheme(),
    Executor: riak.NewExecutorWithRunner(logr.Discard(), noopRunner),
}
```

Controller tests use envtest (`suite_test.go`): create the resource, call `Reconcile` directly, read status back.
Pods need `Spec.Containers`; force cluster `Status.Phase` with `Status().Update`.

## Load and soak tests

`test/scale` (`make scale-test`, `make soak-test`) drives many clusters, users and buckets, or one cluster under a
constant load for hours with OOM, memory and disk watching and a scaling policy. The example client is
`examples/stressapp/riak_stress.py`. Sizing rules (1 GbE carries about 90 MB/s per node), results and charts:
`docs/scaling.md`, `docs/soak-test-results.md`.

## Important Notes

1. **Pod anti-affinity** is configurable with `spec.podAntiAffinity`: `Required` (default, one Riak node per
   Kubernetes node), `Preferred` or `None` (test and small clusters only).
2. **Headless service** `<cluster>-headless` carries inter-node traffic.
3. **Ring size**: use 128 or more (a power of two); it cannot change on an existing cluster.
4. **Configuration** reaches the container as `RIAK_CONFIG_*` environment variables; the image entrypoint
   writes `riak.conf` from them.
5. **Cluster status** is recomputed from live objects on every reconcile.

## Debugging Tips

- Check the cluster is Ready before operating on it
- Pods: `kubectl get pods -l cluster=<name> -w`
- `kubectl exec -it <pod> -c riak -- riak-admin status`. On nodes running under an FQDN, `riak-admin` needs
  `VMARGS_PATH=$(ls -1 /var/lib/riak/generated.conf/vm.*.args | tail -1)`, otherwise it reports "not responding to pings"
- Events and status: `kubectl describe riakcluster <name>`; `kubectl get riakuser` shows the `Cert` column

## Security Review

`/security-review` uses a 3-step agent pattern: an Explore agent lists candidates, parallel Explore agents
apply the false-positive rules to each, and the main agent drops findings below 8/10 confidence.

Known false positives (do not re-flag):
- **Command injection via kubectl exec**: `exec.CommandContext` with an argument array; no shell is invoked.
- **`RIAK_CONFIG_*` injection**: the values come from `RiakCluster.spec.riakConfig`, which needs RBAC write
  access to the cluster resource already.
- **Config value logging in `SetConfig`**: only Riak node settings, no credential material.

Resolved: password authentication was removed; there is no default password.
